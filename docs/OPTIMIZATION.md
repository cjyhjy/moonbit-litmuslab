# 0.2.0 优化与验证

本次保留原有模型、搜索顺序、预算判断和见证语法，重点改进大状态搜索的分配、重放说明和实验保存。0.1.0 的原报告及 ZIP 留在本地 `reports/history/0.1.0/` 与 `release/history/0.1.0/`，新 ZIP 不重复携带历史整包。

## 搜索分配与实测

状态数组按动作复制：读只复制本线程寄存器和 PC，写只复制实际改变的内存或缓冲，刷新只复制内存与对应 FIFO；其余数组只读共享。状态键改用 StringBuilder 直接编码，键的内容保持一致。新增回归测试保留多层父子、兄弟状态，验证后续扩展不污染任何已保存状态。

在本机 Apple Silicon macOS、Node 26.7.0 上，对旧版归档引擎和当前引擎运行三个固定合成负载。每个版本每个负载五次，各用新 Node 进程、相同预热、测量前 GC，并交替先后顺序。下表为中位数；RSS 是整进程峰值，不是只计算搜索堆。

| 固定负载 | 旧版 / 新版耗时 | 耗时减少 | 旧版 / 新版峰值 RSS | RSS 减少 |
|---|---:|---:|---:|---:|
| fence-grid：83,521 状态，完整 | 195.25 / 121.95 ms | 37.5% | 196,368 / 156,368 KiB | 20.4% |
| store-pressure：100,000 状态，达到预算 | 446.69 / 335.60 ms | 24.9% | 240,688 / 198,048 KiB | 17.7% |
| mixed-memory：100,000 状态，达到预算 | 281.26 / 189.13 ms | 32.8% | 228,112 / 180,000 KiB | 21.1% |

每次均要求完整分析 JSON 的 SHA-256 与旧版相同，包含状态计数、截断原因和见证，避免靠少做搜索得到提速。原始样本、输入、引擎哈希与环境见 `research/baselines/performance-0.2.0.json`；当前版本复测用 `python3 tools/benchmark.py`（输出当前源码对应的 `reports/performance.json`）。这些测量仅适用于这三个本机负载，不能推出所有程序或其他硬件上的同等收益。

## 可解释与可保存的实验

每步重放新增结构化 `effect`，指出读值来自共享内存还是本线程 FIFO 中哪一笔写入。FIFO 索引基于执行前状态，队首为 0；初始快照为 null。浏览器使用这些实际语义信息说明步骤并高亮对应缓冲。独立 Python 实现从执行前状态计算 effect，连同状态逐步核对。

浏览器支持下载实验配置、严格导入配置、下载含源程序和运行参数的结果 JSON。导入配置不会直接信任保存结果；应用后由用户重新运行。错误文件保留当前实验，成功导入会取消旧任务并清除旧结果；编辑后禁止导出过期结果。格式与操作见 `API.md` 和 `TUTORIAL.md`。

## 扩大对照并修正证据链

- MoonBit JS、Native、Wasm-GC 各 15 项核心测试；新增分支不变性、状态键格式和最近同地址转发测试。
- 独立 Python 交叉检查 584 用例、2,336 组模型/策略、3,418 条逐步见证；effect 与状态一起比较。
- herd7 原固定 12 组继续匹配，新增 36 个程序 × 2 模型的 72 组真实外部工具完整集合对照。包含负值、寄存器覆盖、连续同地址写、空线程、屏障和边界。
- 超出共同输入域及 herd7 超时的探索案例单独保留，未计入通过数；所有案例均是软件模拟，不是 CPU 硬件实测。
- 参考实现与证据链共 38 项 Python 测试。证据链回归覆盖源码/网页变化、文件增删、旧报告、两个产物模块和精确 ZIP 绑定。

以前的汇总流程可能把旧通过报告附上新文件哈希；现在每个专项报告在执行前记录输入快照、执行后检查未变，汇总再次验证快照。更改输入会拒绝旧报告。干净解包验收覆盖公共 wrapper 和编译模块，重建后再次执行公共 API 交叉检查。包内汇总只声明源码树验收，包外 `release/acceptance.json` 才绑定最终 ZIP，避免归档自引用。

详细当前结果以 `reports/verification.json` 为准。0.2.0 已完整验收并推送；当前 0.3.0 与历史版本的发布和 CI 分别记录，见 `PUBLICATION.md`。
