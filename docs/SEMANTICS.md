# 有限程序与操作语义

## 输入语言

每行一条声明或指令；空行忽略，`#` 起到行末为注释。空格、Tab、CRLF 可用。首个非空行必须是唯一的 `memory` 声明。关键字区分大小写。

```ebnf
program = memory_decl, thread_block, {thread_block} ;
memory_decl = "memory", binding, {binding} ;
binding = identifier, "=", integer ;
thread_block = "thread", identifier, {instruction}, "end" ;
instruction = "store", identifier, integer
            | "load", identifier, identifier
            | "fence" ;
identifier = ASCII_letter, {ASCII_letter | digit | "_"} ;
integer = ["-"], digit, {digit} ;
```

`memory x=0 y=0` 的 `=` 两侧不能有空格。`load r x` 的左参数为当前线程的局部寄存器，右参数为已声明共享地址。线程名、地址名各自在自己的命名空间唯一；同名寄存器在不同线程互不关联。地址、线程和寄存器可同名。

寄存器由 `load` 左参数静态声明，初值 0；重复赋值合法，最终结果取最后一次值。空线程合法。所有名称最长 32 个 ASCII 字符；数字可有前导零，`+1` 不在语法中。

| 资源 | 限制 |
|---|---:|
| 源码 | 32768 Unicode 码点 |
| 线程 | 1–4 |
| 共享地址 | 1–8 |
| 每线程指令 | 0–16 |
| 每线程寄存器 | 0–8 |
| 初值、store 立即数 | −32768…32767 |
| 搜索保留状态数 | 参数 1–100000 |

语法错误给出 1-based 行、Unicode 码点列。输入长度和 API 参数错误使用 0、0。见证错误的 column 表示动作序号或非法字符位置，line=0；消费者应依据错误代码解释。

## 状态

状态为 `(memory, pc[], registers[][], buffer[][])`。共享内存是声明顺序排列的整数数组；每个线程有自己的下一条指令下标、寄存器数组和 FIFO 待写队列。状态内还未执行的寄存器初值固定为 0。

分析时的初态：内存取声明初值，所有 pc=0，所有寄存器=0，所有 buffer 为空。最终状态要求 **每个线程的指令都执行完，且所有写缓冲都清空**。因此线程执行到 `end` 后仍可继续刷新待写队列；半排空状态不作为最终结果。

## SC 转移

选择一个未结束线程，原子执行其下一条指令，并将其 pc 增 1。

- `store a v`：立即令共享内存 `memory[a]=v`。
- `load r a`：令当前线程 `registers[r]=memory[a]`。
- `fence`：无需额外动作，按线程顺序推进。

SC 下所有写缓冲始终为空，不允许 `fN` 刷新动作。

## TSO 转移

有两种可以交错的动作：`tN` 执行线程 N 的下一条指令，`fN` 刷新线程 N 的队首写入。

1. Store：把 `(a,v)` 加到当前线程缓冲尾部，然后推进 pc。缓冲容量由该线程最多 16 条有限指令自然界定，不引入额外硬件容量约束。
2. Load：在本线程缓冲中从最新写入向最旧写入寻找同地址；命中就转发该值，否则读取共享内存。不会读取其他线程未刷新的缓冲。推进 pc。
3. Fence：仅在本线程缓冲为空时启用，再推进 pc。不会替其他线程排空缓冲。
4. Flush：仅在选中线程缓冲非空时启用；弹出队首写入并写入全局内存，不改变 pc。

所有共享内存读写均为同宽度的抽象原子操作。模型采用单一全局内存，不模拟撕裂、多副本传播或缓存层级。此操作系统是教材式 FIFO 写缓冲 TSO 子集，不能据此声称覆盖完整 x86-TSO 的所有指令及异常行为。

## 搜索、结果和预算

搜索从初态出发，用完整状态编码去重。编码包含内存、所有 pc、所有寄存器、各线程 FIFO 的完整内容，不能只按最终寄存器去重。转移采用只读共享：只复制本动作将修改的数组，未受影响的内存、线程寄存器和缓冲可共享。每次写入前都必须复制对应数组；已入图状态不可再变。状态编码改为直接写入 StringBuilder，保留原分隔格式。

BFS 用队列，DFS 用栈，两者共享同一启用关系。每个新状态保存一个前驱和动作；遇到终态时回溯得到一条见证。没有记录全部调度数量；状态数、转移数和结果数不能互相代替。

结果按完整的共享内存和所有命名寄存器归并。结果 `id` 是固定程序内可比较的不透明值；跨不同程序比较请用内存/寄存器字段，不能比较 id。每个结果只返回一条见证；BFS 见证按动作数最短，DFS 不承诺最短。

预算按**保留状态数**计，包含初态。当尝试保留第 `max_states+1` 个不同状态时立即停止并返回 `incomplete/max_states`。已知状态不额外消耗预算。结果预算同理：只有发现第 `max_outcomes+1` 个不同结果才截断。恰好等于预算且可以穷尽的搜索仍是 `complete`。

终态是在出队/出栈时收集；搜索中断时，已发现但尚未展开的终态可能还未列入结果。`incomplete` 的结果子集可能随 BFS/DFS 顺序不同，甚至为空。只有两者都 `complete` 时才要求结果集合一致。该有限图没有循环指令，不需要为当前最终可达性问题附加无限执行的公平性假设。

硬上限控制输入和图规模，不承诺固定毫秒延迟。最坏状态数随线程交错和写缓冲增长。浏览器在 Worker 中计算并支持终止 Worker；CLI 可由运行者中断。

## 见证和证据界限

`replay` 从独立初态开始，每个动作都重新验证启用条件，然后执行转移。无效线程、空缓冲刷新、阻塞屏障、终态后的多余动作、非终态结束均拒绝。

生产重放与搜索共享转移函数，所以二者相互一致不构成独立正确性证明。`tools/reference.py` 是另外编写的不可变状态解释器，交叉验证会逐步比较见证快照。herd7 外部对照另外核对共同子集最终集合。两项证据的实际覆盖及版本见验证报告；有限测试不是所有有限程序的形式证明，也不是实际处理器实验。

## 0.2.0：可解释的读取来源

每个重放快照增加 `effect`，初态为 null。Load 直接报告实际读值及来源 `memory` 或 `buffer`；缓冲来源的 `bufferIndex` 是动作执行前的 FIFO 下标（队首 0），总是指向最新同地址待写项。Store 报告写入目标与入队下标，Flush 报告出队值，Fence 报告本线程缓冲已经为空。界面只展示这些核心字段，不自行猜测读取来源。此元数据由独立 Python 重放逐步验证。
