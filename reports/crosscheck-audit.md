# 独立语义与资源边界审计

审计范围：`core/parser.mbt`、`core/semantics.mbt`、`core/search.mbt`、
`core/replay.mbt`、`core/json.mbt`、`core/types.mbt` 与公开 JavaScript FFI
`dist/engine.mjs`。先完成独立 Python 实现与交叉检查，随后阅读生产源码。
该审计是本项目内部的独立实现复核，不是第三方认证或硬件模型证明。

## 已发现并修复的问题

公开 JS 导出最初直接接收传给 MoonBit `Int32` 的宿主值，未检查类型。
`maxStates = NaN`、`1.5`、`"2"` 可通过范围比较，其中 `NaN` 会使预算比较
始终为假。现有公开 `dist/engine.mjs` 使用 `Number.isInteger` 与范围检查
两个预算，验证 `source`、`model`、`strategy`、`witness` 是字符串，再调用
MoonBit 编译产物。类型包装不实现任何程序解析、内存模型、搜索或重放语义。
正式交叉检查包括 74 项直接宿主类型 probe，现均返回结构化错误。

## 审计结论

修复上述接口边界后，本轮未发现其他需修改的语义或预算缺陷。已核对：

- `parser.mbt:87` 在分词之前限制 32,768 个 Unicode 码点；内存、线程、
  指令、寄存器和标识符长度均有边界。十进制解析每次在数值超过 32,768 后
  立即失败，中间乘法不会接近 Int32 溢出；带前导零的合法值可接受。
- `semantics.mbt:12` 对状态的内存、PC、每线程寄存器和缓冲数组分别复制；
  缓冲项 `Write` 无可变字段，浅复制缓冲项不会造成跨状态修改。
- `semantics.mbt:33` 允许结束指令的线程继续刷新缓冲；fence 等本线程缓冲为空
  才能执行。加载按 FIFO 遍历并覆盖命中值，最后命中即最新同址写转发。
- `semantics.mbt:98` 的状态编码只含定长数组位置、整数和互异分隔符；对同一
  Program 可唯一解码。结果键包含全部内存和全部已命名寄存器，空寄存器数组
  也保留线程位置。状态图去重没有丢失可观察终态字段。
- `search.mbt:75` 仅在终态记录结果。只有发现预算之外的新状态或新结果才
  标记 incomplete；恰好等于上限且遍历完成仍为 complete。已保留见证的
  不完整结果仍是可达证据，不能用来否定尚未发现的结果。
- `replay.mbt:16` 限制 1,024 字符，且最多 128 步；合法程序最多 64 条指令，
  每条 store 最多再对应一次 flush，因此 128 是足够的合法动作上限。每步
  重新查询启用动作，末尾再次检查所有 PC 耗尽且缓冲为空。

## 资源与证据范围

交叉检查另实际执行了两个大状态用例：四线程各 16 条 fence 的 SC 搜索完整
遍历 `17^4 = 83,521` 个状态；四线程各 16 条 store 的 TSO 搜索在保留
100,000 状态后明确返回 `incomplete / max_states`。最大 128 步 TSO 见证
也由 Python 与 MoonBit 逐步对照。精确计数、版本、源码与编译产物 SHA-256
见 `crosscheck.json`；时间只描述这次本机运行，不构成性能基准。

状态数量预算不是墙钟时间或进程内存限额。模型仍仅限文档定义的无分支有限
SC/TSO DSL；这些测试不能扩展为完整 x86、ARM、C/C++ 内存模型或真实硬件
行为的正确性证明。外部 oracle 证据单独记录，本报告不代替外部对照。
